## Why This Exists

The rest of this repo shows what a PM does. This section shows how a PM thinks.

Any competent PM can write a PRD or run a retro. The harder thing — and the thing that separates good PMs from great ones — is knowing when the framework doesn't apply, when the data is wrong, when to push back, and when to make the call anyway.

These documents are that part.
