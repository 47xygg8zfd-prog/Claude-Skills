# PM Operating System

A PM without a system spends their time answering questions that should have already been answered. Which features are we building next and why? What does success look like? Who decides? What changed last week? These aren't hard questions — but without a repeatable structure for answering them, they consume the hours that should go toward actual thinking.

A PM Operating System is the collection of templates and frameworks that make recurring work fast, consistent, and legible to everyone around you. It's not bureaucracy. It's the difference between a team that moves with clarity and one that relitigates the same decisions every sprint.

This OS was built at Pulse — a Series B B2B analytics platform running 2-week sprints with an 18-point velocity. It's opinionated by design. Generic templates produce generic output.

## What's in this OS

| File | Purpose |
|------|---------|
| `prd-template.md` | Production-ready PRD — from problem statement to decision log |
| `prioritization-framework.md` | RICE scoring with practical guidance and the cases where you should override it |
| `weekly-review-template.md` | Weekly product review — status, metrics, decisions, risks, next week |
| `daci-template.md` | Decision ownership framework — who drives, who approves, who informs |

## How to use it

Treat these as starting points, not sacred documents. Adapt the templates to your context. The goal is a system that reduces decision overhead, creates shared memory across the team, and lets you spend your thinking time on the hard stuff — not on formatting.
